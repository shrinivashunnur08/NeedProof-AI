## Demo script (~2 minutes)

1. Open **Start guided demo**. Point out **OFFLINE REPLAY · FICTIONAL DATA** labeling. Explain the decisions are generated by NeedProof's Python engine but the on-screen replay does not contact merchants.
2. Choose **Merchant claim**. Outcome must be provisional; there must be no buy button or purchase authorization.
3. Select **Now remove reported stock**. Outcome should change to a *more evidence needed* state; do not imply a real store became unavailable.
4. Choose **Conflicting sources**. Explain how contradictory specifications block a recommendation.
5. Choose **No candidates**. Show the system requests further discovery rather than inventing availability.
6. Show the five-stage decision trace. Keep source types, evidence origin and any assumed probabilities visible. Make it clear that BI aggregates are illustrative and separate from the buyer journey.

## Interaction and UX acceptance

- Mouse and keyboard can reach every scenario and decision-trace button. Check Tab, Shift+Tab, Enter/Space and visible focus indicator.
- Test all nav items. Use browser Back, Forward and Refresh; there should be no silent navigation breakage.
- Visual consistency: headings, labels, line length and contrast remain legible at 100% and 125% browser zoom.
- Empty, loading and failure states are visibly described for any active live features. Offline replay must remain usable when backend feature flags are off.
- Inspect browser Console and Network tabs for unexpected errors. **Never paste Firebase ID tokens, App Check tokens, cookies or secrets into reports.**
- A local build does **not** prove hosted Auth/App Check, CORS, Firestore IAM, merchant owner authorization or cloud cost ceilings.
- Check the `index-*.js` warning. Performance should be measured on a throttled mobile browser; a large bundle does not automatically fail QA but must be assessed before hosted release.

## Release gate (approval required)

**Local-only gate:** scripts/verify_chunk16c3.cmd passes + manual acceptance matrix complete + no purchase-safety regression.

**Hosted gate:** requires explicit user approval to incur possible usage; verify Firebase Auth, App Check, CORS, merchant isolation, real Firestore access, Cloud Run traffic and environment flags, quotas, and rollback. Do not deploy from this package.

**Cost note:** The existing Cloud Run/Places project is billing enabled. A free-tier estimate or budget alert cannot guarantee zero charges. For strict zero additional cloud spend, keep existing live features unchanged and demonstrate the offline replay locally or via a separately approved static-hosting workflow after reviewing quotas.
