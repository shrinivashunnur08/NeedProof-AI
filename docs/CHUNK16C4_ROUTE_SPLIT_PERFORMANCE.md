# Chunk 16C.4 — Reduce startup by isolating public React routes

**Goal:** An optional local, safe-first bundle optimization. This is NOT a hosted release or a guarantee of faster mobile load.

## What changed

The previous `App.tsx` imported the public showcase and the full internal workspace at module load, although public mode rendered only the showcase. This patch uses lazy route imports, moving the original internal application unchanged to `NeedProofWorkspace.tsx` and retaining `/verify/<id>` behavior. It prevents unnecessary workspace code from being eagerly pulled into the public judge-facing route. Some vendor dependencies shared with the showcase may still be large.

A temporary, accessible branded loading state appears while the selected route loads. Existing backend APIs, security gates, feature flags, Firestore rules and the compact sidebar are unchanged.

## No-cost safety

No `gcloud`, `firebase deploy`, token, App Check, IAM, runtime API, provisioning or cloud requests are included. `npm run build` uses local dependencies and static configuration. Backups under `backup_16c4_route_split/` stay untracked. This does not verify or hard-cap cloud costs.

## Manual browser acceptance before commit

- Public local run: `cd frontend`, `set VITE_PUBLIC_SHOWCASE=true`, `npm run dev`, open printed URL; check sidebar, demo navigation, four scenarios, no unexpected authentication prompts, no console errors and no horizontal clipping on mobile.
- Native workspace local run: in a NEW CMD `cd frontend`, `set VITE_PUBLIC_SHOWCASE=false`, `npm run dev`; confirm normal internal workspace loads. This may use existing network-enabled features; do not trigger billable API actions.
- Test the route `/verify/123` only in non-public mode without a live token; expected safe reject/error UI. Do not paste real tokens into logs or screenshots.
- Chrome DevTools Network > Disable cache and Lighthouse mobile: observe initial JS, load time and errors. Bundle decrease does not itself prove perceived performance gain.
- **No deployment yet.** On hosting rollout later, build with `VITE_PUBLIC_SHOWCASE=true` and validate its mode before uploading.

## Rollback

Before committing, restore `frontend/src/App.tsx` from `backup_16c4_route_split/App.tsx` and delete `frontend/src/NeedProofWorkspace.tsx` ONLY if it was generated by this patch. The script refuses to overwrite local edits. After committing, use a separate Git revert/rollback review; do not reset unrelated user work.
